# FINDaero CHANGELOG

The aviation industry, change by change.

FINDaero CHANGELOG показывает проверенные изменения российской гражданской авиации. Лента и карта строятся по `data/events.json`; карточки включают даты, авиакомпанию и ссылки на источники. Фильтр, поиск, сортировка и сравнение используют записи из этого реестра. Новая запись не попадает в публичную ленту, пока не получит статус verified и две ссылки-источника.

Проект настроен на публикацию статического сайта через GitHub Pages. Workflow `.github/workflows/webpack.yml` автоматически собирает сайт после каждого push в ветку `main`.

## Запуск

Нужен Node.js 20.19 или новее (проект проверяется на Node.js 24).

```bash
npm install
npm run dev
```

Затем открыть http://localhost:3000. Production-сборка создаётся командой `npm run build` в папке `out`.

Парсер и правила отбора RSS-кандидатов можно проверить без сети командой `npm run validate:discovery`. Ручной предварительный просмотр живой ленты: `npm run discover:news:dry-run` (требуется доступ к RSS AEX.RU).

## Статус

Публичный сайт остаётся статическим и размещается на GitHub Pages. Лента содержит редакционно проверенные записи из `data/events.json`; поиск, фильтры, сортировка, сравнительный экран и карта работают по этим данным. Каждый опубликованный факт содержит две ссылки на источники. Страницы перевозчиков генерируются из `data/airlines.json`; один реестр используется каталогом, статическими профилями и Prisma seed. В профиле можно искать по тексту события, типу и регистрации самолёта, аэропортам и маршруту, фильтровать историю по категории и переключать сортировку между датой события и обнаружения. Для каждой подтверждённой регистрации также строится отдельная карточка самолёта с хронологией событий и источниками; неизвестные интервалы и операторы не додумываются. В разделе SOURCES можно фильтровать реестр по типу, HTTP-доступности и искать по названию, сайту или ограничениям. Ссылка на правила повторного использования указывается только если известная ссылка на политику действительно добавлена; домашняя страница источника не считается такой политикой. Проверка экспорта убеждается, что все страницы и фильтры сгенерированы. GitHub Actions раз в сутки проверяет HTTP-доступность зарегистрированных URL и сохраняет технический отчёт для SOURCES.

Отдельный ежедневный workflow **Daily aviation news discovery** читает RSS-ленту AEX.RU и создаёт до восьми кандидатных Issues для редакционной проверки. Он сохраняет только заголовок RSS, дату и ссылку на оригинал; статью, описание и изображения не копирует. Кандидаты остаются неопубликованными, требуют проверки редактором и двух источников, а workflow работает только в приватном GitHub-репозитории. Это ограниченный мониторинг одного отраслевого RSS-источника, а не полный обзор рынка. Остальные источники пока проверяются вручную; ежедневная HTTP-проверка не подтверждает наличие RSS/API и сама по себе не означает разрешения на сбор или переиздание.

### Локальная база данных

Нужны Docker Desktop и Node.js 18.17 или новее. Скопируйте `.env.example` в `.env`, затем выполните:

```bash
docker compose up -d db
npm install
npm run db:generate
npm run db:migrate
npm run db:seed
```

Seed добавляет только названия авиакомпаний из начального списка ТЗ. Локальные учётные данные из compose-файла предназначены только для разработки; не используйте их на сервере. Перед production-сборкой запускается `scripts/validate-news.mjs`, который блокирует публикацию записей без двух корректных HTTPS-источников.

## Загрузка в GitHub через браузер

1. Создать репозиторий на GitHub и загрузить в него содержимое распакованного ZIP (не сам ZIP).
2. В репозитории открыть **Settings → Pages** и выбрать **GitHub Actions** в разделе Build and deployment.
3. Открыть вкладку **Actions**. Workflow развернёт сайт; адрес появится в результате запуска и в Settings → Pages.
4. Для автоматической публикации последующих изменений загружать их в ветку `main`.
5. Не добавлять `.env` и секреты. Файл `.env.example` безопасен для публикации.
6. Ежедневная техническая проверка URL запускается workflow **Daily source availability check**. Её отчёт доступен в разделе **Actions → запуск → Artifacts**; успешный HTTP-ответ не подтверждает доступность RSS/API или права на использование публикаций.
7. Кандидаты из RSS видны в **Issues** с меткой **needs-review**. Не одобряйте их автоматически: откройте оригинал, проверьте факт, дату и независимое подтверждение, затем подайте отдельную заявку через форму события.

Если репозиторий называется `имя.github.io`, GitHub Pages может публиковать его в корне домена. В текущей настройке используется адрес проекта `https://имя-пользователя.github.io/имя-репозитория/`.

Если GitHub предложит загрузить архив целиком, не загружайте ZIP как единственный файл: распакуйте его и загрузите файлы проекта, чтобы GitHub показывал исходный код.

## Проверка и публикация новых событий

Публичный сайт размещается на GitHub Pages и не содержит серверной админки. Очередь редакционной проверки работает через GitHub Issues, а действия модератора — через GitHub Actions:

1. Откройте **Issues → New issue → Предложить авиационное событие** и заполните форму. Заявка остаётся вне сайта.
2. Проверьте дату самого события, прочитайте два разных источника, сверьте категорию и тип события. Не копируйте тексты публикаций и фотографии.
3. Поставьте метку **publish-approved** только после проверки. Workflow сверит права редактора, поля, HTTPS-ссылки, тип события, даты и дубликаты; затем сохранит событие и журнал решения, добавит использованные ссылки в реестр источников и запустит сборку Pages. Если перевозчика ещё нет в каталоге, workflow создаст профиль с его названием и безопасным URL-slug; официальный сайт не указывается, пока редактор не добавит и не проверит его вручную.
4. Для запроса уточнений поставьте **needs-more-information**, для отказа — **rejected**. Эти решения записываются в `data/moderation-log.json`.

При первом использовании откройте **Settings → Actions → General → Workflow permissions** и разрешите Actions запись в репозиторий. Workflow использует встроенный `GITHUB_TOKEN`, не требует PAT, пароля или секретов в исходниках. Если в репозитории включена защита `main`, разрешите этот контролируемый workflow обновлять ветку либо используйте правила, допускающие обновление от GitHub Actions. Любая публикация видна в истории коммитов и запускает штатный workflow деплоя.

Это GitHub-native модерация для статического Pages-сайта, а не отдельная веб-админка. Автоматический сбор ограничен кандидатами из одной RSS-ленты и не публикует события; остальные источники проверяются вручную.
