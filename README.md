# FINDaero CHANGELOG

The aviation industry, change by change.

FINDaero CHANGELOG показывает проверенные изменения российской гражданской авиации. Лента и карта строятся по `data/events.json`; карточки включают даты, авиакомпанию и ссылки на источники. Фильтр, поиск, сортировка и сравнение используют записи из этого реестра. Новая запись не попадает в публичную ленту, пока не получит статус verified и две ссылки-источника.

Проект настроен на публикацию статического сайта через GitHub Pages. Workflow `.github/workflows/webpack.yml` автоматически собирает сайт после каждого push в ветку `main`.

## Запуск

Нужен Node.js 20.19 или новее (проект проверяется на Node.js 24).

```bash
npm install
npm run dev
```

Затем открыть http://localhost:3000. Production-сборка создаётся командой `npm run build` в папке `out`.

## Статус

Публичный сайт остаётся статическим и размещается на GitHub Pages. Лента содержит редакционно проверенные записи из `data/events.json`; поиск, фильтры, сортировка, сравнительный экран и карта работают по этим данным. Каждый опубликованный факт содержит две ссылки на источники. Автоматический сбор, веб-админка и API не настроены: доступность интерфейсов источников и разрешения на повторное использование ещё требуют отдельной проверки. Новости не являются автоматическим мониторингом всего рынка.

### Локальная база данных

Нужны Docker Desktop и Node.js 18.17 или новее. Скопируйте `.env.example` в `.env`, затем выполните:

```bash
docker compose up -d db
npm install
npm run db:generate
npm run db:migrate
npm run db:seed
```

Seed добавляет только названия авиакомпаний из начального списка ТЗ. Локальные учётные данные из compose-файла предназначены только для разработки; не используйте их на сервере. Перед production-сборкой запускается `scripts/validate-news.mjs`, который блокирует публикацию записей без двух корректных HTTPS-источников.

## Загрузка в GitHub через браузер

1. Создать репозиторий на GitHub и загрузить в него содержимое распакованного ZIP (не сам ZIP).
2. В репозитории открыть **Settings → Pages** и выбрать **GitHub Actions** в разделе Build and deployment.
3. Открыть вкладку **Actions**. Workflow развернёт сайт; адрес появится в результате запуска и в Settings → Pages.
4. Для автоматической публикации последующих изменений загружать их в ветку `main`.
5. Не добавлять `.env` и секреты. Файл `.env.example` безопасен для публикации.

Если репозиторий называется `имя.github.io`, GitHub Pages может публиковать его в корне домена. В текущей настройке используется адрес проекта `https://имя-пользователя.github.io/имя-репозитория/`.

Если GitHub предложит загрузить архив целиком, не загружайте ZIP как единственный файл: распакуйте его и загрузите файлы проекта, чтобы GitHub показывал исходный код.
